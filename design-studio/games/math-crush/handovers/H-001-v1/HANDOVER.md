## MC-003 — longer-chain scoring
Base = 100 + 25×(n−2). Multiplier: n=2 →1; n=3 →1.5; n=4 →2; n=5–8 →3. Award floor(base×multiplier), once per committed valid chain. Examples: 2→100; 3→187; 4→300; 5→525; 8→750. Display the rounded final points, e.g. 125 ×1.5 →187. Explosion bonus is separate and never multiplied. Finish bonus remains 50×unused moves. No streak or score for a wrong sum. Quota advances exactly once per valid chain, however many candies explode. Add points before checking quota success, and check success before zero-moves failure.

## MC-004 — earning special candies
Prototype defaults: stripes introduced from level 4; wrapped from level 7. At levels 1–3 no special rewards. Levels 4–6: chains of 4+ earn a horizontal striped candy. Levels 7–12: exactly 4 earns striped; 5–8 earns wrapped. Shorter chains earn none. One reward maximum per move, including a move activating old specials. Reward replaces the LAST selected cell after the removal set is resolved, retaining that cell's numeric value but receiving a fresh tile ID and special type. It then participates in normal downward gravity; it is not removed or activated in the same move. The reward exists only if the level continues; on a winning move just show its celebratory badge, do not refill. Show reward preview while holding a valid eligible chain. No specials spawn randomly.

## MC-005 — activation, explosions and deterministic resolution
A special activates when its existing cell belongs to the valid chain OR the blast closure. Stripe clears its full horizontal row. Wrapped clears the clipped 3×3 square centered on itself. Special numeric value counts normally only when directly selected in the chain. Evaluate the sum first; a wrong sum never activates anything. Compute all affected cells on the pre-gravity board. Process newly hit specials in row-major order, each ID once, until closure. Removal set is union(chain, blasts), with each cell counted once. Blast bonus = 25×count(removal set minus selected chain). The reward from MC-004 is created AFTER closure; no recursive reward explosion. Credit selected-chain points and blast bonus, consume one move, advance quota once. Then win/loss; if continuing, remove union, place reward, collapse down preserving survivors, refill seeded RNG and validate solvability.

If refill has no legal chain, replace the board per BASELINE, losing specials, with “Board refreshed”; no penalty. Undo restores it if requested. Always preserve one legal chain; never promise the next board contains a long chain. Row example: selected [0,1,2,3] sums 10, index2 is striped, index4 is blast-only →300+25=325. The reference image's 350 uses an incorrect four-tile base and omits that extra bonus and is not the implementation total. Wrapped and recursive examples are in data/mechanics-fixtures.json.

MC-004/005 acceptance: ordinary chains, threshold levels, numeric special selection, invalid activation, two overlapping specials, edge 3×3 clipping, chain reaction, fresh-reward immunity, final-move success, seeded repeatability and Undo all verified. Reduced motion uses a brief fade, never removes effects from the game model.

## MC-006 — score-based stars (prototype default)
Replace move-based stars for Match only. Failure gives no stars. Completion always gives one. Two stars: coreScore≥200×quota. Three: coreScore≥300×quota. coreScore includes chain, blast and unused-move points, excludes any speed bonus. Thus quotas 3/4/5 use thresholds 600/900, 800/1200, 1000/1500. Hints do NOT cap stars in this prototype; show Assisted in result and save that flag separately. Undo also marks Assisted. This removes v1's hidden one-star penalty and keeps the comparison transparent. Show thresholds before play and progress on result; do not fill rating stars midgame. Thresholds are unvalidated initial tuning, not claimed achievable by every seed: verify at least one no-speed three-star route per level with the real engine or report and propose a threshold correction before claiming full balance. Do not silently change level data to fit them.

## MC-007 — optional speed bonus experiment
Default OFF. Pause/settings has “Speed bonus (experimental)”; changing it affects NEXT attempt only. No countdown or loss from time. When enabled, show a small count-up clock, starting on first committed move (valid or wrong), ending on win/loss. Count active playable time only: pause, hidden document, tutorial, resolution and results excluded. Resume baseline timestamp on return; persist elapsed active milliseconds, never wall-clock timestamps for offline accrual. Bonus on success = floor(100×max(0,1−activeSeconds/(30×quota))); failure gives 0. Example quota3: 0s→100, 45s→50, ≥90s→0. Display separately from coreScore and star calculation; cap makes it modest and excludes speed from star eligibility. Separate best scores for timed/untimed attempts. This is an optional comparison, not a mandatory timer approved by the owner.
