Schema3 in data/levels.json: `levels[]` with unique integer id1..12; rows/cols5; stable contentVersion journey-v1; world enum garden/chocolate/frosting; shape full/hourglass/ring; active sorted unique indices0..24; values length25 (inactive=null, active integer1..9); operation add/multiply; targets nonempty positive integer array; objective chains/jelly; quota positive for chains,0 for jelly; jelly unique active terrain indices, nonempty only for jelly; moves positive; rewardMode none/stripe/both; specials map string cell-index to stripe/wrapped on active cells; seed nonzero uint32; freeInvalid bool; openingWitness legal path; starThresholds increasing positive integers; releasePhaseB/D. PhaseB content1–10, D11–12. Field values are authoritative.

`made` counts committed valid chains; current target=targets[min(made,lastIndex)]. For sequences the chain quota equals sequence length. For fixed targets length1 repeat until objective complete. The number of valid chains is NOT a jelly win requirement. Stage labels use current remaining jelly or made/quota. For jelly: evaluate valid chain, resolve all explosions, remove jelly under each removed cell, decrement moves and add points, then test all jelly gone before out-of-moves. The final board may remain behind the result; don't spawn new tiles after victory. No points for jelly itself; avoid scoring it twice. Reward on cleared jelly cell doesn't recreate jelly. Initial specials remain on retries, separate from completed tutorial flags.

## Masks, gravity and repair
Active terrain immutable within attempt. A void breaks selection adjacency; cursor may skip over it, selected path may not. Stripe crosses voids and hits active cells on both sides; wrapped/combo rectangles intersect active mask. No candy ID in void, no score for it. Jelly mask is also immutable terrain except removing a layer.

Each column is split into contiguous runs of active cells by voids. Process columns left→right, then segments top→bottom. Gather surviving candies top→bottom within each segment, put new candies ahead of survivors, and map result top→bottom; no falling through a void. A top segment can spawn at its own top, a lower segment at its own top—show a small sugar entry glint there, no implied portal. Fill-order determines RNG. Keep survivor IDs/specials; fresh IDs monotonically increment (oracle compares values/specials, production tests also compare IDs).

New content uses xorshift32: uint32 x from nonzero seed; x ^= (x<<13) masked uint32; x ^= x>>17 unsigned; x ^= (x<<5) masked uint32; store masked x; value1+(x mod9). See data/model.py. Classic keeps its existing mulberry RNG. Make sure JS uses unsigned shifts and final >>>0; no Math.random in model.

After a non-winning commit, advance made/target first, settle, then search legal chains for NEW operation/target. If none: redraw all active cells in ascending index order, clear all specials but retain jelly terrain and target/moves/score; choose lexicographically first adjacent active pair a<b. For addition inject max(1,target−9), target−first. For multiplication inject lexicographically smallest factor pair2≤a≤b≤9. Current targets guarantee those pairs exist. Assert rather than inject illegal digits if future data changes; reject invalid configuration at load. “Board refreshed” feedback, no penalty. Undo restores the complete pre-action snapshot including removed specials/jelly/RNG. No automatic matching/cascades; only intentional chains and triggered special effects.

Multiplication DFS cannot stop at exact product before8 tiles: appending1 remains legal. Can prune if product>target or target%product≠0. Additive pruning remains positive-sum. No eval of expression strings. Free wrong attempts don't change made,target,RNG,score,moves or history (except transient feedback sequence ID). Wrong charged attempt decrements moves and is undoable; never fires specials. Invalid geometry is ignored by gesture layer; doesn't become a legal arithmetic submission.
